# RacingDash native reuse: bounded expressions and CAN TX admission

Date: 2026-10-25. Profile: `sport-gdi6`.

This increment reuses the existing **C engine**, not a Python interpreter on the
ECU. It is a reproducible host component and compatibility test. It is not a
flashable rusEFI target, a complete ProjectTree runtime, or a CAN hardware driver.

## Implemented boundary

`firmware/runtime/racing_dash_guard.{h,cpp}` provides:

| Boundary | Implemented behavior |
| --- | --- |
| Pure expression | One admitted expression, at most 512 bytes, 128 opcodes including END, 32 stack values and 32 input channels |
| Bytecode admission | Operand lengths, stack underflow/overflow, exact one result, mandatory final END, no trailing bytes, known opcode subset |
| Input schema | Unique IDs 100..8191, integer/boolean/state domain with explicit min/max, required freshness timeout 1..INT32_MAX ms |
| Runtime inputs | Coherent caller snapshot, exact ID/order, explicit valid flag, timestamp age, per-domain ranges |
| Output | Typed/ranged value or explicit fault with value 0; no output-channel write or actuator authority |
| Configuration replacement | Failed load disables execution; it cannot silently continue the previous program |
| Memory ownership | Private fixed native contexts, owned bytecode/schema, no allocation, no copy/move that could alias native context pointers |
| CAN admission | Classical CAN buses 0/1, standard/extended ID bounds, periodic mode, DLC 1..8, 1..8 Intel integer signals, bounded non-overlapping bit fields, fresh/ranged source data |
| CAN scaling | Positive nonzero numerator/denominator, checked int64 scaling and signed/unsigned destination range; no truncation to fit |

`run()` calls the original `VM_Execute()` after validation. It does not reimplement
formula evaluation. All referenced inputs must be valid, including references
in branches not selected by `if`: the existing VM is eager, not short-circuit.
Timestamp subtraction supports a uint32 rollover; a future or ambiguously old
timestamp is rejected. The caller must invalidate input samples across reset.

The native numeric semantics remain scaled int32: arithmetic wraps in two's
complement, division truncates, and right-shift parity is tested on this host.
An output range check does **not** prove that a wrapped intermediate expression
was physically sensible. This increment does not grant such expressions control
of injection, ignition, DBW, HPFP or protection overrides. Explicit unit/scale
metadata and physical interval/overflow rules remain a graph-schema task.

The wrapper currently admits ordinary stack operations, arithmetic, comparisons,
logic, bitwise operations, min/max/clamp and `if`. Division/modulo require a
proven nonzero literal divisor (a negated literal is accepted); dynamic divisors
are rejected instead of inheriting the native zero-divisor-to-zero behavior.
Lerp requires a literal weight 0..1000. MAP and SWITCH await their own arithmetic
and operand contract. Indexed channel operations and channel stores are
forbidden. Table/timer/filter opcodes are rejected because the native handlers
currently push 0 rather than evaluate those nodes.

The CAN validator is a separate precondition check. It must run on the same
coherent snapshot used for packing, and again before a delayed transmission
where needed. There is no physical transmit function in the new integration.
Native CAN TX packing is executed only by the host test callback. Validation of
one snapshot is never permission to keep sending its old values indefinitely.

## Findings that constrain reuse

These findings refer to the pinned source, not an assumed newer RacingDash.

| Source | Verified behavior | ECU consequence |
| --- | --- | --- |
| `shared/vm/vm.c`, `VM_AddProgram` / `VM_Execute` | Unknown opcodes and incomplete operands do not produce an explicit execution fault; stack helper overflow/underflow is silent | Admit and own bytecode before native execution |
| `vm.c`, table/timer/filter opcode cases | Four handlers skip the operand and push 0 | Reject these opcodes; actual node managers must be integrated separately |
| `vm.c`, `VM_BuildExecutionOrder` | Dependency scan follows PUSH_CH; cycles can leave programs unexecuted without a cycle error; self-dependencies are excluded | Do not reuse this as a validated ECU graph scheduler |
| `channel.c`, `Channel_GetValue` / `Channel_IsLive` | Reads do not propagate stale/invalid flags; an unknown channel is considered live by IsLive | Separate strict input schema and per-snapshot validity gate |
| `firmware/CM4/src/dash_channels.c`, `DashChannels_Tick` | Stage order is math, filters, tables, stateful, timers | Preserve or explicitly change one-tick dependencies; do not claim global same-tick DAG evaluation |
| `shared/can_tx/can_tx.c`, `build_message` | With nonzero scale_den, division is by scale_num; zero scale_num is not rejected by CanTx_Add | Reject zero numerator before invoking native code; regression included |
| `can_tx.c`, packers | Native config admission does not enforce legal bit widths/extent; big-endian indexing is not by itself proof of DBC Motorola compatibility | Validate width/extent; initial wrapper admits Intel only |
| `can_tx.c`, `build_message` | Encoding is `(channel * scale_den / scale_num) - offset` | Preserve this exact rule; DBC physical offset conversion needs explicit adapter |
| `can_tx.h`, `CanTxSendFunc` | Callback returns void | No queue-full/bus-off/backpressure acknowledgement contract yet |

## Tests and reproduction

```text
python Power8GDI/firmware/tests/run_racing_dash_tests.py
```

The runner needs a C11 compiler plus a C++17 compiler. It compiles the unchanged
vendor `.c` sources as **C**, links the C++ wrapper/tests, and needs neither Qt,
pytest, the original RacingDash checkout nor an ECU. It is included in both
`run_all_host_tests.sh` and `tools/run_checks.py --suite host`. Optional
`--sanitizers` uses UBSan on a supporting Linux/macOS toolchain; that was not run
on this Windows host.

Observed result: **PASS**, Clang 21.1.6, Windows x86_64, optimized build with
warnings as errors. Only vendor unused-parameter warnings are suppressed;
vendor source is unmodified. Tested:

- 10 actual compiler vectors: arithmetic, fixed division/modulo, eager logic,
  clamp, bit operations, lerp, negative shift and int32 wrap boundary;
- every strict truncation of these vectors, forbidden/stub/unknown commands,
  invalid stack/result/end, exact operation/stack limit boundaries and byte cap;
- all 256 single-opcode mutations at an expression boundary;
- invalid/stale/future/mismatched/range-failing inputs, timestamp rollover,
  output type/range rejection and failed replacement invalidation;
- real native packing/periodic dispatch into a capture callback on buses 0/1,
  11-bit/29-bit IDs, scaled unsigned and signed values, nonzero native offset;
- zero scale divisor, overlapping or oversized signals, DLC/ID/mode/byte-order
  errors, absent source, stale inputs, destination overflow, all 256 bus values
  and all 256 bit-length values.

The full host runner was also executed: all six C++ build/test pairs and this
new RacingDash native suite passed. Its overall result remains **FAIL** at this
firmware worktree base because the system Python lacks pytest and the legacy
schematic-vs-CSV test finds DIN5..8 versus MOTOR3/4 labels. Those failures are
recorded separately; they are not counted as firmware passes.

On this host `sizeof(Expression)` is **88,392 bytes**, mostly inherited native
channel/VM capacity. This is not a satisfactory per-node MCU allocation: a full
graph must share bounded engine contexts rather than instantiate one wrapper
per node. Neither STM32 WCET nor RAM/linker fit has been measured. Compile-time
operation limits bound work; they are not a measured execution-time guarantee.

## MAP-04 / ProjectTree follow-up contract

1. Keep the existing bounded Map4D/P4DM scalar codec and golden vectors; it is
   independent of six-cylinder channel counts. Validate immutable maps when
   publishing configuration, rather than scanning 4096 cells on every lookup.
2. Define one versioned schema for channel ID, unit, scale, numeric type,
   source bus, value validity, timestamp/age, ownership and generation. Distinguish
   electrical bus 0/1 from human-facing CAN1/2 consistently.
3. Compile a bounded graph with explicit cycle errors, unique writers, maximum
   node/edge/cost counts and deterministic ordering. Treat feedback as explicit
   delayed state, never an accidental self-reference.
4. Reuse the separate RacingDash table/filter/timer managers after defining
   their state initialization, tick interval, timeout behavior and reset rules.
   Test the full graph against preview with missing/stale data and rollover.
5. Admit configuration atomically; prevent partial graph publication and define
   whether timer/filter states reset or migrate. A failed new graph must not
   leave unreviewed outputs latched. This wrapper currently disables its program.
6. Connect CAN RX to coherent typed snapshots. Add the DBC Motorola/scaling
   adapter, mux handling and conversion golden vectors. CAN TX needs bounded
   queue depth, total bus load/rate budgets, retry/drop counters, backpressure,
   bus-off handling and freshness checks at final submission.
7. Keep formula outputs as requests to native policy modules. Fuel cut, DBW,
   injection/ignition deadlines, overboost/overspeed and other protections retain
   native priority and output gating. No VM program may bypass them.

No Lua runtime or TunerStudio INI dependency was added. The own-client transport,
MCU scheduling, complete graph engine and physical CAN HAL remain pending.
