# Активное ТЗ: спортивный Power6GDI

Дата решения пользователя: 25.10.2026. Это решение заменяет число каналов из
`SCOPE_2026_10_23_HUGE_GDI8.md`. Пользователь явно выбрал переделку платы строго
под шесть цилиндров, а не программный профиль на восьмицилиндровой плате.

Историческое имя каталога `Power8GDI/` пока сохраняется для совместимости
генераторов и путей. Оно не определяет активное количество каналов.

## Подтверждённая аппаратная цель

| Узел | Активная цель |
|---|---|
| DI | 6 бортовых каналов, peak-and-hold; две независимые секции драйверов |
| PI | 6 опциональных каналов для смешанного DI+PI |
| ТНВД | 2 независимо планируемых канала клапанов |
| Зажигание | 6 цилиндровых каналов |
| Моторные мосты | Ровно 2: один DBW и один EWG |
| Широкополосная лямбда | 1 бортовой контроллер |
| Детонация | 2 датчика с назначением цилиндрам |
| CAN | 2 обязательные шины |
| SENT / LIN | Обязательная поддержка; состав подключаемых устройств не зафиксирован |
| VVT | Впуск и выпуск; точное число исполнительных механизмов зависит от двигателя |
| EGT | 1 измерительный канал; прежний внешний модуль остаётся рабочей архитектурой, протокол предстоит выбрать |

Пользователь указал брать силовые решения из **rusEFI Power4GDI**. Генераторы,
схема, профили драйверов и номиналы должны иметь проверяемые ссылки на конкретную
ревизию исходной схемы. Число каналов не является доказательством допустимого
тока, длительности импульса, тепловой мощности или совместимости внешней нагрузки.

Уточнение пользователя 25.10.2026: **DI — B58B30 Gen2; PI — «IDX1050»**.
Это выбранные внешние нагрузки, а не компоненты BOM самой платы. Точный BMW/Bosch
артикул DI и его токовый профиль ещё не подтверждены; параметры Vboost,
peak/hold, времени открытия и безопасного закрытия не копируются из другого
семейства форсунок. Схема PI рассчитана на высокоомные форсунки. Вероятное
соответствие пользовательского «IDX1050» семейству Injector Dynamics ID1050x /
ID1050-XDS требует сверки маркировки перед выпуском окончательной калибровки.

Первичные данные для этой сверки:
[Injector Dynamics ID1050-XDS](https://injectordynamics.com/injectors/id1050-xds/),
[официальные калибровочные таблицы](https://help.injectordynamics.com/support/solutions/articles/4000074340-link-engine-management).
Производитель указывает для семейства 1065 cc/min при перепаде 3 bar на бензине
52°C; это не универсальный расход в mg/ms для любого топлива и давления.
Неподтверждённые параметры нагрузки сохраняются в реестре открытых инженерных
решений, а не заменяются произвольными рейтингами.

## Порядок работы, заданный пользователем

1. Доработать электрическую схему новой платы, проверить соединения, корпуса,
   назначение сигналов и состав компонентов. Прежняя разводка не является
   доказательством правильности новой схемы.
2. Получить BOM непосредственно из конкретной версии новой схемы. Затем
   оценить стоимость компонентов, PCB, монтажа и разовых расходов для одной
   и десяти полностью собранных плат. Старый восьмиканальный BOM не является
   итоговым BOM Power6GDI. Данные с неполным MPN помечаются явно.
3. Перестроить согласованный со схемой PCB-кандидат, продолжать размещение,
   трассировку и устранение реальных ERC/DRC ошибок.
4. Развивать прошивку на подтверждённой аппаратной модели; отделять host-тесты
   от реального MCU build, стенда и испытаний двигателя.
5. Развивать существующий конфигуратор, сохраняя результаты предыдущей работы.

## Прошивка и собственный клиент

Функциональное ТЗ и исходный анализ находятся в
[пакете исследования](research/2026-10-25-sport-ecu/README_RU.md).
Сохраняются MAP/modelled fuel, STFT без LTFT, Flex Fuel, DI+PI, поцилиндровые
коррекции, Fuel Film, ХХ, VVT, EWG, турбоскорость, защиты, nitrous,
launch/ALS/shift/overrun и нативные PWM-PID. Lua исключается.

Собственный клиент обязателен. В репозитории уже есть Python/PyQt6 редактор:
это существующая база реализации. Открытые компоненты rusEFI tuner можно
адаптировать; TunerStudio и INI не становятся обязательной зависимостью продукта.
Нельзя преобразовывать старую восьмицилиндровую калибровку в шестициллиндровую
молча или включать запись в ECU до проверки протокола и возможностей устройства.

## Дополнение интерфейса по скриншотам пользователя

Обязательные функции клиента: тест выходов; назначение входов/выходов;
APS/DBW/VVT/VE tuner; выбор устройств и имени/VIN; reconnect/disconnect;
kill engine/reboot/RTC; проект offline/online; загрузка базовой карты;
частичный export/import и merge; просмотр логов; обновление и восстановление
прошивки; явное сохранение в постоянную память; настройки приборов и горячих
клавиш; комментарий проекта; DTC; отчёт памяти; Tune Display; Logged Channels;
Project Tree; Variables Inspector; Smart Grid Panel.

Дерево проекта: CAN RX, CAN keyboard, timer, table, number, logical function,
CAN TX, группы и импорт CANX/DBC. Состояния simulated/offline/connected должны
быть различимы. Перечень требований не означает, что все команды реализованы.

**VM engine и работа с CAN берутся из собственного проекта Racing Dash** по
прямому указанию пользователя. Сначала фиксируются исходная ревизия, зависимости
и тестовые примеры; затем адаптируются совместимые компоненты. Нативный VM для
ECU требует ограничений по времени/памяти, типам, состоянию и полномочиям.
Сервисные команды и тест выходов должны проверяться также на стороне ECU.
